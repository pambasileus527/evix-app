# システムの構造（Vercel と Supabase の役割）

```
ブラウザ ──(1) ページを開く────────▶ Vercel（Next.js：画面を返す）
   │
   └──(2) 登録・ログイン・マイカー──▶ Supabase（認証・データベース・RLS）
```

- **Vercel**：画面（HTML・JS）を配信するだけ。登録の可否やデータの保存は決めない。
- **Supabase**：メール登録・ログイン・マイカー／アラートの保存を担当する。ブラウザから直接つながる。

## 環境変数

Vercel の Settings > Environment Variables に次の2つが必要（Type は Config）。`NEXT_PUBLIC_` の値はビルド時にコードへ埋め込まれるので、追加・変更したら Redeploy する。

| 名前 | 値 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co`（Vercel の公開URLではない） |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_...` |

任意：`NEXT_PUBLIC_SITE_URL`（公開URLが `evix-app.vercel.app` 以外のとき。サイトマップ等に使う）

**やってはいけないこと**：`service_role` / `secret` キーやデータベースのパスワードを、コード・`.env.example`・GitHub に入れない。

## Supabase 側の設定

- Authentication > URL Configuration
  - Site URL：公開URL
  - Redirect URLs：`公開URL/**` と `http://localhost:3000/**`
  - 確認メールのリンクの行き先を決める設定
- Authentication > Sign In / Providers > Email：「Confirm email」をオフにすると、確認メールなしで登録できる
- データベース：`supabase/migrations/0001_cars_alerts.sql` を SQL Editor で実行する（テーブルと RLS を作る）

## ログイン状態

- ログイン状態はサイトごとに別。`localhost:3000` と公開サイトは別々になる
- 未ログインで `/mycar` を開くと `/login` に移り、ログイン後に元のページへ戻る（`src/middleware.ts`）
- ヘッダーの「マイカー」「ログアウト」はログイン後だけ表示する（`src/components/AuthNav.tsx`）
